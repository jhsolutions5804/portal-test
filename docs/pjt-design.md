# PJT 관리 리빌드 설계서 (초안 · 2026-10-13)

> 대표님 결정(2026-10-13): **Ph2·Ph4·경량PJT를 정확히 똑같은 모듈로 통합한다. 그러려면 두 타입의 기능·디자인 통합이 먼저다.**
> 이 문서는 현재 구포털 PJT 3개 앱을 조사한 결과(① 현황 ② 기능 비교 ③ 데이터 경로 ④ 디자인 비교)와, 그 위에서 정한 통합 기능 명세 초안(⑤), 대표님이 정해 주셔야 할 것(⑥)을 담는다. 코드는 ⑥이 정해진 뒤에 시작한다.
> 방식은 영업기획과 같다: 저장 값은 바꾸지 않고(동결) → 새 규칙을 순수 함수로 → 본섭 실데이터로 되짚어 대조 → 화면 묶음마다 대표님이 테섭에서 확인.

## ④ 디자인 비교

- 세 앱 모두 **같은 모양의 모바일 우선 화면**(상단 탭바 5개, 카드, 폭 480~640px 고정 래퍼)이다. 차이는 래퍼 폭(Ph2·Ph4 480px / 경량 640px)과 PC 전환 폭(899px / 520px)뿐이고 색·글꼴은 같다.
- 새 모듈은 세 앱의 모양을 한 벌로 합치고 **포털 공통 디자인 시스템**(`jh-` 토큰, 사이드바, 카드, 칩)을 쓴다. 폰에서는 하단 탭, PC에서는 사이드바 + 넓은 본문.

## ⑤ 통합 기능 명세 (초안)

**통합 원칙**: 프로젝트 종류(Ph2·Ph4·경량)는 "데이터 경로 설정"과 "기능 켜기/끄기"로만 다르고, **화면과 코드는 한 벌**이다. 한 프로젝트를 고르면 같은 7개 탭이 열린다.

| 탭 | 통합 명세 |
|---|---|
| 홈 | 공정율·D+·이달 공수·오늘 출역·바로가기·오늘 일정·최근 공사일보 (Ph2/Ph4 홈 + 경량 홈 합집합) |
| 일정 | 경량의 풍부한 등록 폼(시간/할 일, 장소, 참석자, 완료 처리) + 카테고리 10종 + 2주 보기 |
| 공정 | **섹터(선택 사항) → 품목 → 단계(프로젝트가 정함)** 모델. Ph2·Ph4는 섹터가 있고 단계는 4개(반입·입고검사·설치·시공검측)로 설정, 경량은 섹터 없이 자유 단계. 날짜별 체크·누적, 수정 모드, 품목 일괄 등록, 공정표 PPT |
| 근태·공수 | 경량의 기능(전체 출역 체크·일괄 적용·인원별 누적·최근 7일·이미지 저장) + 팀장·마스터 명부 선택 + 월 집계표 — 모든 프로젝트에 |
| 공사일보 | 경량 방식(출역·공수 자동 반영, 사용 장비, 미리보기·PDF)을 기본으로 하되 Ph2·Ph4 기존 일보 양식과의 차이는 ⑥ D3 |
| 연명부 | PJT 모듈 안(프로젝트 참여 인원 기준) |
| 설정 | 기본정보·품목·물량·시작일·상태·**공정 단계 설정**·**참여 부서·개인**·**기능 켜기**(장비 배치도, 주간 공정회의 PPT) |

**Ph2에만 있던 기능(장비 배치도, 주간 공정회의 PPT)**은 "프로젝트 설정에서 켜는 선택 기능"으로 두고 모든 프로젝트가 쓸 수 있게 한다(처음에는 Ph2만 켬).

**저장 방식**: 통합 화면 뒤에 **데이터 접근 어댑터**를 둔다 — (프로젝트, 종류) → 위 ③ 표의 경로. Ph2·Ph4는 기존 컬렉션 경로를 그대로 쓰고, 경량(및 앞으로 생길 새 프로젝트)은 `pjt_registry/<id>/…`를 쓴다. 데이터 이전 없음 → 영업기획 읽기 경로 불변, 본섭 영향 없음. (모든 프로젝트를 `pjt_registry/<id>/…` 한 형식으로 옮기는 이전은 나중 과제로 두고 지금은 하지 않는다.)

## ⑦ 근태·공수 탭 — 조사 결과와 합친 규칙 (2026-10-13)

구포털 3개 앱을 읽고 본섭 데이터(Ph2 공수 문서 67일·Ph4 9일)로 확인한 것:
- **저장 형식은 같다**: 출역 `{checks:[id…]}`, 공수 `{md:{id:숫자}}`(날짜별 문서). 공수는 0~3, 소수 첫째 자리, 0이면 지움 — 본섭의 모든 공수 값이 이 규칙 안에 있다(새 규칙으로 읽어도 바뀌는 값 없음).
- **출역 체크와 공수는 따로 움직인다**: Ph2 본섭 데이터에서 공수는 대부분 2(320건)이고 출역만 있고 공수 없는 건이 48건, Ph4는 출역 체크 없이 공수만 입력한 건이 6건이다. 그래서 **출역을 체크할 때 공수를 자동으로 채울지는 프로젝트 설정**(`defaultManday`)으로 둔다 — 경량은 지금처럼 1, Ph2·Ph4는 지금처럼 자동 입력 없음.
- **합친 규칙**(`app/modules/pjt/attendance.js`): 공수 입력·±조정·전원 일괄 적용, 출역 토글·전체 출역(대상이 모두 체크면 해제), 재직 판정(퇴사일 당일부터 제외), 팀장(게스트)은 본인·자기 팀원만, 인원별 누적, 최근 7일 합계, 월 집계표(그 달 1일 재직자 + 월 중 퇴사자).
- **경량 구포털의 결함을 고쳤다**: 경량의 공수 저장은 "현재 명부 인원"의 공수만 다시 써서 명부에 없는 사람의 공수를 지웠다. 새 규칙은 읽어 온 전체 맵에서 한 사람만 고쳐 쓴다.
- **어댑터**(`app/modules/pjt/adapter.js`): 프로젝트 키(`p4ph2`·`p4ph4`·`reg_<id>`) → 위 ③ 표의 경로와 켜진 기능. 영업기획의 공수 연동(`plan/issue.js`)이 읽는 경로와 같은지 시험이 교차 확인한다.

### 대표님 규칙 (2026-10-13) — 확정
1. **공수를 입력하면 출역도 자동으로 체크된다**(공수 > 0). 공수를 0으로 지우면 공수만 지우고 출역은 그대로 둔다. 반대로 **출역을 해제하면 그 사람의 공수도 비운다**(출역과 공수는 함께 간다 — 공수가 있는 사람을 해제할 때는 화면에서 먼저 확인). 옛 기록의 "공수만 있는 날"(Ph4 6건)은 출역으로 센다. *출역 해제 시 공수를 비우는 부분은 춘식이가 규칙을 이어 정한 것이라 대표님 확인이 필요하다.*
2. **퇴사일 전날까지의 공수는 나온다.** 10/11 퇴사면 10/10까지 입력·표시되고 10/11부터 입력 대상에서 빠진다(기존 규칙 유지). 단 그날 이미 출역·공수가 기록된 사람은 퇴사 후 날짜여도 보인다.
3. **퇴사 처리한 사람의 공수도 나온다.** 월 공수 집계표는 그 달 1일에 재직 중이던 사람(월 중 퇴사자 포함)에 더해, 명부에서 빠진 사람의 공수도 "(명부에 없음)" 행으로 보여 줘서 합계에 포함한다. 본섭 데이터로 확인: Ph2 2026-06(w4 22공수)·07(w4 6공수), Ph4 2026-03(w10·w11·w12 합 8공수)·07(합 19.6공수)에서 집계표 합이 원본 문서 합과 모두 일치한다.
4. 앞으로 새 모듈에서는 근로자를 "명단에서 제거"(명부 문서 삭제)하지 않고 **"투입 종료"(비활성)**로 둔다(D7 제안 — 위 규칙 3의 취지).

### 영업기획 쪽 확인 필요 (대표님)
- 영업기획의 **지급예정서 공수 연동·팀별 노무비는 현재 명부에 있는 사람의 공수만 더한다**(경량PJT 옛 ID 중복 집계를 막으려는 규칙). 그래서 이미 명부에서 빠진 **Ph2 w4(28공수), Ph4 w10~w12(19.6공수)**는 그 집계에서 빠져 있다. 위 규칙 3은 새 PJT 화면의 집계표에 적용하고, 영업기획 집계를 바꿀지(명부 밖 공수를 지급 대상에 넣을지)는 해당 공수가 실제 지급 대상이었는지 확인한 뒤 정한다 — 대기열 점검 항목.

## 진행 방침

- 첫 단계(테섭 반영): **데이터 접근 어댑터 + 근태·공수 화면** — `app/modules/pjt/`(adapter·attendance·projects·attend-view·index), 시험 순수 규칙 24건 + 저장 동작 점검 1개 시나리오. 구포털 PJT 메뉴 안에 **"👷 출역·공수 (새)"** 항목으로 열린다(주소 `#/pjt/attend/<프로젝트>/<날짜>`) — 구포털 Ph2·Ph4·경량 항목은 그대로 두고 같이 쓴다. 한 화면에서 프로젝트를 골라 Ph2·Ph4·경량을 모두 처리한다(저장 경로는 어댑터가 결정).
- 화면 배치(대표님 피드백 2026-10-13): **넓은 화면은 왼쪽에 일하는 영역(프로젝트·날짜·요약·인원별 출역과 공수, 좁게), 오른쪽에 탭 — 이달 공수 집계표(기본)·인원별 누적·최근 7일·명단 관리** 를 항상 보여 준다. 입력하면 집계표·누적이 이미 읽은 값에 끼워 넣어 바로 갱신되고(다시 읽지 않음), 날짜가 다른 달로 넘어가면 집계표도 그 달로 바뀐다. 폰은 한 열(일하는 영역 아래에 같은 탭).
- 대표님 결정(2026-10-13): **공수 체크·집계·명단은 모두 프로젝트별**(화면 위에서 프로젝트를 고르면 그 프로젝트의 명단·집계표·누적이 나온다. 구포털 항목을 교체하면 각 프로젝트의 탭이 된다). **마스터 명부는 근로자 연명부**에 있고, 프로젝트 명단에서는 거기 있는 사람을 투입·종료만 한다(이름·생년월일 등 정보 수정은 연명부). 집계표에는 **주말·공휴일 표시**(일요일·공휴일 빨강, 토요일 파랑, 요일 글자, 공휴일 이름은 머리글에 마우스를 올리면), 누적 공수는 **월별**(사람 × 달, 월 합계·전체 합계).
- 화면 기능: 프로젝트·날짜 이동(오늘은 새벽 6시 전이면 전날), 인원별 출역 체크·공수(−/＋ 0.5, 직접 입력 0~3), 전체 출역·전원 공수 일괄, 최근 7일 합계, 이달 공수 집계표(월 이동), 인원별 누적 공수, 명단 관리(마스터 명부에서 투입, **투입 종료·재투입 — 명부 문서를 지우지 않음**). 팀장(게스트)은 본인·자기 팀원만, 팀장 지정이 없는 게스트는 읽기 전용.
- 다음: 공정 탭 → 일정 → 공사일보 → 연명부 → 설정. 근태·공수를 대표님이 써 보신 뒤 구포털 PJT 항목의 근태 탭과 교체한다.
- 본섭 직원 QC 기간에는 본섭에 새 변경을 올리지 않는다(테섭에서만 진행). 현장 직원이 매일 쓰는 화면이므로 화면 묶음마다 대표님 확인 후 다음으로 넘어간다.
