# 본섭 일괄 패치 준비 문서 (테섭 → 본섭)

작성 기준: 테섭 build **20261012w** (커밋 7299ea8 이후). 방침(대표님 확정): **테섭 구축을 끝낸 뒤, 코드 전부 + 현재 본섭에 저장된 데이터를 합쳐 본섭에 한 번에 패치한다.**
이 문서는 그때 쓸 반영 순서·데이터 이전·제거 대상·확인 목록이다. 이식이 진행될 때마다 이 파일을 갱신한다.

## 0. 큰 그림

- 테섭과 본섭은 **별도 Firebase 프로젝트**다(테섭 `portal-test-…`, 본섭 `p4ph2-fab-506a7` 계열). 새 코드는 구포털과 **같은 컬렉션 이름·필드**를 쓰므로, 본섭에 새 코드를 올리면 본섭의 기존 데이터를 그대로 읽는다(데이터를 옮겨 담을 필요가 없는 것이 원칙).
- 테섭에서만 만들어진 데이터(재무회계 장부 입력분, 총무 입력분, 시험용 근로자·계약서 등)는 **본섭으로 복사하지 않는 것이 기본**이다. 필요한 것만 §3의 방법으로 본섭에서 다시 넣는다.
- 본섭 패치는 **복구 지점을 만든 뒤** 한다(§5).

## 0-2. 인사 모듈 전수 점검 결과 (2026-10-13)

구포털 테섭 파일 기준으로 탭 18개·컬렉션·전역 함수·버튼 문구를 새 화면과 대조했다.
- **빠졌던 기능을 채움**: 근로자 명부의 **보유 자격증 편집**(기술수당 1개당 — 급여명세서가 읽는 값인데 입력 화면이 없었음), 휴직/퇴직 원서 상세의 **"퇴직금 정산으로"·"근로자 명부"** 버튼(버튼은 있었으나 동작이 없었음), 근로자 명부 상세·인사 변동의 **계약서 이동 링크 3곳**(옛 주소라 끊어져 있었음 → 해당 근로자의 계약서·새 계약서 작성으로 연결).
- **의도적으로 옮기지 않음**: 급여명세서의 초과근로 "연동 확인" 디버그 도구, 근로시간의 "전체 데이터 초기화" 위험 버튼 2개, 구포털 파일에 섞여 있는 정산서·기성(`invoice_history`·`payment_history`·`progress_checks_`·`worker_manday`) 잔여 코드(인사 탭이 아님).
- **확인하지 못한 것**: 현재 테섭에 적용된 보안 규칙(저장소에는 10/1 백업만 있음) — 본섭 패치 전에 Firebase 콘솔의 현재 규칙을 내려받아 §2 컬렉션별로 대조할 것. 새 화면을 실제로 눌러 본 QC(§6).

## 1. 반영 순서 (본섭)

1. **복구 지점**: Firestore 내보내기(전체) + 보안 규칙 파일 백업 + 코드 저장소 태그(`prod-before-cutover`) + 서버 함수 현재 버전 기록. (§5)
2. **서버 함수 재배포**: `identityAct`(주민번호 암호화 보관 — §0-1, 본섭에 없으면 근로자 등록·번호 변경·열람이 실패) 및 `edoc-functions-ledger_20261011h.zip` (저장소 `portal-functions` 2a65615 이후). 내용: 운행일지(`drive`) 문서는 결재 없이 즉시 확정, 월간 수지 `saveMonthlyPlan`. 
   `firebase deploy --only functions:edoc --project <본섭 프로젝트>` (테섭에서는 `--project test` 로 같은 절차를 이미 쓴다).
3. **보안 규칙 반영**(`firestore.rules`, 테섭·본섭 모두):
   - ⚠️ 규칙의 `isEdocCollection()`·`isAdminOnlyCollection()` 은 "기본 허용(승인 계정 전체)에서 **제외**"하는 목록일 뿐 접근을 **허용하지 않는다**. 제외만 하면 관리자에게도 막힌다(2026-10-13 테섭에서 겪음). 아래 세 가지를 **모두** 해야 한다.
   - ① 총무 컬렉션 5개(`'general_leases'`, `'general_vehicles'`, `'general_assets'`, `'general_renewals'`, `'general_drive_history'`)를 **`isAdminOnlyCollection()`**(기본 허용에서 제외) 과 **`isHrDataCollection()`**(관리자 읽기·쓰기 허용 — `match /{hrCol}/{document=**}` 가 이 목록을 씀) **둘 다**에 추가. 추가 전에는 직원 누구나 읽을 수 있으므로 **총무 데이터를 넣기 전에** 반영.
   - ② 운행일지: `isEdocCollection()` 목록에 `'edoc_drive'` 를 넣고, **`match /edoc_overtime/{docId}` 아래에 전용 블록**을 추가 — `match /edoc_drive/{docId} { allow read: if canViewEdocDoc(); allow create: if canCreateEdocDraft(); allow update: if canEditEdocDraft(); allow delete: if false; }` (다른 전자결재 문서와 같은 규칙).
   - ③ 반영 후 총무 화면(임대·차량·자산·갱신 일정)과 운행일지가 **관리자 계정으로 열리는지**, 일반 직원 계정으로는 막히는지 확인.
   - 인사 새 화면이 쓰는 컬렉션은 모두 구포털이 이미 쓰던 것이라 별도 규칙 추가는 없다(§2 표). 단 `hr_calendar_access/config` 의 이메일 목록은 **본섭 값 그대로** 유지.
4. **코드 반영**: 테섭 저장소(`jhsolutions5804/portal-test`) 최종 빌드를 본섭 저장소에 반영. 반영 전 `app/core/config.js` 등 **환경 설정이 본섭 Firebase 를 가리키는지** 확인(테섭 설정이 섞여 올라가지 않게). 빌드 번호·`version.json` 확인.
5. **데이터 후처리**(§3) → **QC**(§6) → 구포털 제거 대상 정리(§4).
6. 문제가 있으면 §5 절차로 되돌린다.

## 4. 구포털에서 제거할 대상 (이식 완료 후)

- 구포털 인사 화면(`hr/index.html`)의 **"근로시간"(초과근로) 탭** — 새 "초과근로 현황 + 출퇴근 달력"과 겹침(자동연동 중복 위험). **가장 먼저 막을 것.**
- 새 화면으로 대체된 탭: 근로자 명부, 연차 현황(등록·수정·사용촉진 제외), 인사 변동, 공고 관리, 채용 지원자, 연봉 제안서, 근로자 면담, 휴직/퇴직 원서, 퇴직금 정산, 해고예고통지서, 인사 캘린더, 인사평가, 급여테이블, 급여명세서, 연봉계약서, 근로계약서.
- **원격 서명 링크·QR·본인 열람 링크·메일 발송**(연봉 제안서·급여명세서·연봉계약서·근로계약서)은 **새 화면으로 이식 완료**(`hr/sign.js`·`hr/sign-io.js`). 서명 페이지 `sign.html` 은 별도 공개 페이지로 그대로 쓴다(§9-1).
- **연차 등록·수정·삭제, 연차사용촉진도 이식 완료** → **구포털 인사(`hr/index.html`)의 모든 기능이 새 화면으로 옮겨졌다.** 본섭 반영 후 QC 가 끝나면 구포털 hr 를 통째로 걷어낼 수 있다(단 `sign.html`·`sign_links` 규칙은 유지).

## 5. 복구(롤백) 절차

1. **패치 전**: `gcloud firestore export gs://<버킷>/pre-cutover-YYYYMMDD` (전체), 보안 규칙 파일을 `backup/` 에 날짜 붙여 보관, 저장소 태그 `prod-before-cutover`, 서버 함수 현재 배포 버전 기록.
2. **코드만 문제**: 저장소를 태그로 되돌려 재배포(데이터 구조는 구포털과 호환이므로 데이터 복구 불필요).
3. **규칙 문제**: 백업한 규칙 파일을 다시 배포.
4. **함수 문제**: 이전 zip 으로 재배포.
5. **데이터 오염(예: 자동연동 중복)**: §3-3 의 `overtime` 중 `edoc_` 로 시작하는 문서만 선별 삭제 후 `edoc_overtime.linkedToOvertime` 을 되돌려 다시 연동 가능. 필요 시 내보내기본에서 컬렉션만 복원.

## 8. 이식 과정에서 구포털과 달라진 동작(의도한 변경)

- 인사 홈: 재직 인원·계약 갱신·급여명세서 미작성 집계에서 **퇴직자 제외**(구포털은 명부 전체를 세어 퇴직자가 "연봉계약서 없음"으로 잡혔음). 서명/도장 **삭제가 실제로 필드를 지움**(구포털은 merge 저장이라 삭제가 반영되지 않았음). 도장 이미지는 360px 이내로 줄여 300KB 이하만 저장.
- 업무 흐름 바로가기 15칸은 인사 홈에서 빼고 왼쪽 사이드바가 대신함.

- 급여테이블: 학력 트랙·학력 차등 제거(직급·호봉별 단일 표), 최저시급 변경 시 사원 1호봉 자동 갱신.
- 공고: 학력 선택지·기본 문구의 학력 줄 제거(`education` 은 빈 값으로만 저장).
- 출퇴근 달력(관리자 입력): 휴게 기본값을 출퇴근 모듈과 같게(5시간 이하 0분), 근무시간 소수 2자리, 출근=퇴근 거부.
- 초과근로 자동연동: 신청서 번호 고정 번호로 한 번만 반영. 초과근로 입력 시간 0 초과 24 이하.
- 연봉계약서: 새 계약서 시작일 기본값을 오늘로(구포털은 옛 고정일).
- 날짜 검사: 없는 날짜(2월 30일) 거부.
- **급여명세서(2026-10-13~)**: 4대보험 요율을 급여 월의 법정 요율로 계산(2026: 국민연금 4.75%·건강 3.595%·장기요양 13.14%)하고 새 양식 v7 로 저장 — 구포털(본섭·테섭)은 옛 요율. 본섭 반영 시 이미 발행된 명세서는 저장 당시 양식 그대로, **과거분 차액 정산 방식은 별도 결정**(docs/statutory-alignment.md §5).
- **퇴직금 정산(2026-10-13~)**: 임금총액=지급계(기술수당·휴일근로·특별성과급 포함), 퇴직일=마지막 근무일 다음 날, 월중 퇴직 일할, 연간 상여·연차수당 3/12 가산, 지급기한 안내 — 구포털 계산과 값이 달라진다(보통 더 큼).
- **근로자 명부**: 공제대상 가족 수·자녀 수·원천징수 비율 칸(worker_private) 추가.
- **근로계약서·연봉계약서(2026-10-13~)**: 계약기간(시작일·종료일)을 비우면 저장되지 않음(구포털은 근로계약서를 기간 없이도 저장). **연차 관리자 등록**: 기간을 바꾸면 일수를 평일 수로 자동 계산(구포털은 직접 입력).
- 인사총무 메뉴: 인사/총무 두 갈래 + 인사 아래 단계별(채용·입사·재직·변동·퇴사) 묶음.

## 9. 원격 서명·메일 발송 — 반영 시 주의

1. **`sign.html` 은 환경별 Firebase 설정이 들어 있는 파일**이다(테섭 저장소의 것은 테섭 프로젝트를 가리킨다). **본섭 저장소의 `sign.html` 을 유지하고 테섭 것으로 덮어쓰지 않는다.** 단 이 파일 안에는 **계약서 양식 사본(현재 v6)** 이 들어 있어(파일 주석: "DOC_TPL_CURRENT 가 올라가면 이 파일도 함께 갱신"), 본섭 `sign.html` 이 v5 이하라면 **양식 사본 부분만 v6 로 갱신**해야 새 서명 링크 미리보기가 v6 와 같아진다(Firebase 설정은 건드리지 않음). 새 화면은 자신이 올라가 있는 곳의 `sign.html`(상대 경로)로 링크를 만들므로 코드 자체는 환경 설정이 필요 없다.
2. `sign_links`(+하위 `secure/payload`·`secure/result`)와 `doc_send_log` 의 **보안 규칙은 구포털이 이미 쓰던 것**이다. 본섭 규칙에 그대로 있는지만 확인한다(없던 규칙은 추가하지 않았다).
3. 서명 결과 반영(`syncSignedLinks`)은 이제 **새 연봉·근로계약서 화면을 열 때** 돈다. 구포털 계약서 탭도 같은 일을 하므로 두 화면을 동시에 처음 여는 일은 피한다(이미 반영된 건은 `synced` 표시로 다시 반영되지 않음).
4. 메일 발송은 EmailJS(서비스·템플릿·공개 키는 구포털과 같은 값)이며, 브라우저에서 SDK 를 CDN 으로 불러온다.
5. 링크 생성에는 받는 분의 **휴대폰 번호**(근로자 명부 또는 채용 지원서)가 필요하다(문자 인증용). 번호가 없으면 안내 후 중단된다.
