# 프로젝트 월간 보고서 설계안 (r1 · 2026-10-17)

이 문서는 공개 저장소에 있으므로 **금액·개인 급여·고객사 이름을 쓰지 않는다**(구조와 규칙만). 실제 숫자는 화면·비공개 문서에서만 본다.
관련 설계: `margin-design.md`(마진율), `pjt-log-design.md`(이력 로그 — 월간 보고서 인입은 그 문서의 §10 순서 4), `platform-queue.md` 1-2.

## 0. 목적
프로젝트가 진행되는 동안 **한 달에 한 번, 버튼 하나로** 그 달의 공정·출역·공수·공사일보를 한 장으로 모으고(현장 층), 청구·지급·원가·마진율·수율을 함께 보는(경영 층) 보고서를 만든다. 사람이 엑셀로 모으지 않아도 **수율·마진율 계산이 수월**해지고, 월간 인사 보고서("월 마감 흐름")와 같은 틀로 일관되게 본다.

## 2. 구성
### 2-1. 현장 층 (프로젝트 화면 · 금액 없음)
1. **공정**: 월말 누적 공정율, 그 달 새로 체크한 칸 수, 그 달 새로 설치 완료된 품목(장비) 수, 섹터별 증감
2. **출역·공수**: 월 출역 일수, 일평균 출역 인원, 월 투입 공수 합, 인원별 공수는 **합계만**(개인별 일당·금액 없음)
3. **생산성 수율**: 그 달 새로 완료된 품목 수 ÷ 투입 공수(§3). 데이터가 부족하면 숫자를 내지 않고 사유를 표시(§4)
4. **공사일보**: 작성 일수·미작성 일수(**달력 전체 기준**, 결정 11 — 괄호에 출역 있는 날 중 미작성 병기), 비고(특이사항) 모음, 다음 작업(내일 작업) 요약
5. **이력 요약**: 그 달에 생긴 변경·결정·요청(분류별 건수), 기한이 지난·남은 요청 목록 — 이력 로그에서 가져옴
6. **다음 달 계획**: 공사일보의 마지막 "내일 작업"과 기한이 다음 달인 이력 요청 + 직접 입력 한 칸

### 2-2. 경영 층 (영업기획 쪽 · 지정자만)
1. **청구·지급**: 그 달 청구 공급가액·지급 공급가액·누계, 수금 여부(청구 발행 시점에 매출 인식, `margin-design.md`)
2. **원가**: 직접원가(전표 프로젝트 표시) + 직접 노무비(공수 비율 배분 + 4대보험 추정 가산, "추정 포함")
3. **마진율**: (청구 공급가액 − 직접원가 − 직접 노무비) ÷ 청구 공급가액, 목표 마진율과 비교
4. **노무 수율**: 청구 공급가액 ÷ 직접 노무비
5. **원가 달성률**(간이 역산, §3-3)

## 3. 계산식
### 3-1. 생산성 수율 (현장 층)
`생산성 수율 = 그 달에 새로 완료된 품목 수 ÷ 그 달 투입 공수 합`
- **완료 물량** = 공정 체크 데이터(`progress_days/<날짜>` — 날짜마다 "그날 새로 체크한 키"만 저장)에서 **그 달 날짜들의 합**. 누적이 아니라 **월 증분**이라 날짜 문서를 월 범위로 읽어 합하면 된다.
  - **완료 물량 = 새로 설치 완료된 품목 수**(대표님 확정). 설치 완료 = **설치 하위 열(`installCols`)이 모두 체크된 품목** = **시공검측 직전까지의 설치 단계가 모두 끝난 품목**이다. **시공검측은 설치 완료에 포함하지 않고 별도 단계로 분리**한다(공정 구조에서 시공검측은 설치 하위 열 밖의 마지막 단계 — 이미 코드의 "설치" 합성 단계 정의와 같다).
  - 반입·입고검사는 설치 이전 단계이므로 수율의 분자가 아니라 **참고 지표**로만 보여 준다(월 증분).
  - 증분 계산은 "그 달 마지막 날까지의 완료 품목 수 − 전달 말까지의 완료 품목 수"로 한다(체크를 취소하면 줄 수 있으므로 문서 합이 아니라 **상태 차이**로 계산).
- **투입 공수** = 그 달 `manday/<날짜>` 문서의 공수 합(출역한 날만). 프로젝트마다 별도 저장소이므로 프로젝트별로 합한다.
- 표시는 "공수 100당 완료 품목 N" 같은 **읽기 쉬운 단위**로 환산해 보여 준다.
### 3-2. 노무 수율 (경영 층)
`노무 수율 = 청구 공급가액 ÷ 직접 노무비` — 1.0 이상이면 노무비를 청구가 덮는다.
### 3-3. 원가 달성률 (경영 층, 간이 역산)
`목표 원가 = 견적 공급가액 × (1 − 목표 마진율)`, `달성률 = (실제 직접원가 + 직접 노무비) ÷ 목표 원가`. 100% 이하면 목표 원가 안. 진행률(공정율)과 함께 봐야 하므로 "공정율 대비 달성률"(= 달성률 − 공정율)도 보여 준다.

### 3-4. 프로젝트 완성도 — 시공검측 이후 (현장 층, 대표님 2026-10-17: "시공검측 이후는 다른 기준으로 프로젝트 완성도 체크")
공정 구조(품목 × 단계 체크)는 **시공검측까지**만 있다. 검측 이후(보완·마감·시운전·준공 서류 등)는 품목 단위 체크가 아니라 **프로젝트 단위 일**이므로 같은 방식으로 세지 않고 **별도 지표**로 둔다. 보고서의 공정 칸을 이렇게 나눈다:
1. **설치 완료율** = 설치 완료 품목 ÷ 전체 품목, 월 증분(수율의 분자)
2. **시공검측 통과율** = 시공검측 통과 품목 ÷ 설치 완료 품목(검측을 신청·통과하는 속도), 월 증분
3. **마감 완성도**(검측 이후) = **프로젝트가 정한 "마감 체크리스트"의 완료 항목 ÷ 전체 항목**. 체크리스트의 **항목 이름은 프로젝트 설정에서 프로젝트마다 직접 정한다**(코드에 단계 이름을 박지 않는다 — 프로젝트마다 검측 이후 거치는 일이 다르므로). 항목마다 완료일·담당·메모를 남기고, 월 증분은 그 달 완료된 항목 수.
- **수율과의 관계**: 설치가 거의 끝나 **설치 완료 증분이 0인 달에 마감 작업에 공수가 들어가면** 생산성 수율이 0으로 나와 "생산성이 없다"로 오해된다. 그래서 프로젝트의 설치 완료율이 100%에 가까운(예: 95% 이상) 달부터는 **수율 칸에 "마감 단계"를 표시하고, 설치 수율 대신 마감 완성도 증분과 그 달 공수를 함께 보여 준다**.
- 마감 체크리스트는 **새 데이터**(프로젝트 설정 + 월별 완료 기록)라 이력 로그처럼 서버 함수 경유·규칙 직접 접근 거부로 둔다. 1단계에서는 설치 완료율·시공검측 통과율만 만들고 마감 체크리스트는 2단계.

## 4. 데이터가 부족할 때 — 숫자 대신 사유
**실제 데이터로 점검한 결과(2026-10-17)**: 처음에 테섭 데이터로 계산하니 7·8월에 공수는 큰데 공정 체크가 거의 없어 수율이 0 으로 나왔지만, **테섭의 공정 데이터가 6월 말에 옮긴 낡은 복사본이어서 생긴 착시**였다. **본섭의 실제 공정 체크(51일치)로 설치 완료를 월말 누적으로 세면** 월 증분이 선명하게 나오고(설치 완료 0 → 41 → 86 → 102 품목, 시공검측 통과는 8월부터 시작해 9월에 전부), 이 증분을 같은 달 투입 공수로 나누면 의미 있는 수율이 된다. 즉 **기준(설치 완료 = 시공검측 직전까지)은 실제 현장 입력과 잘 맞는다.** 다만 현장 입력이 끊기는 달은 앞으로도 있을 수 있으므로 아래 규칙은 그대로 둔다:
- 그 달 **설치·검측 체크가 전혀 없고 공수는 있으면** 수율을 **숫자로 내지 않고 "공정 체크 없음(작업 입력 누락 가능)"** 으로 **표시만** 한다(결정 9 — 경고·알림 없음).
- **공수가 없는 달**(0 또는 문서 없음)은 "공수 입력 없음"으로 표시한다(0 나눗셈 방지).
- 수율은 항상 **분자·분모를 같이** 보여 준다("설치 완료 +45 ÷ 공수 195").
- 경영 층 마진율·노무 수율도 **재료가 부족하면**(전표에 프로젝트 표시가 없음, 공수 비율 합이 맞지 않음) 숫자 옆에 **"추정"·"자료 부족"** 표지를 붙이고 계산에 쓴 재료를 접어서 보여 준다(`margin-design.md` §5).
- **월 공수 자료는 2026-06 이후만 있다**(본섭 기준) — 그 이전 달은 현장 층의 공수·수율을 만들지 않는다.
- **본섭 전환 때 옮겨야 할 것**: 본섭 P4 Ph2·Ph4 의 공정은 옛 구조(날짜별 컬렉션 `progress_checks_<날짜>`, 섹터 문서의 `checks` 맵)이고 새 구조(`pjt_registry/<id>/progress_days/<날짜>`)와 키 형식(`<품목>_<열>`)은 같다. 전환 이전 달의 월간 보고서는 옮긴 데이터로만 만들 수 있다.

## 5. 특이사항·다음 달 계획의 자동 채움
- **공사일보**(`reports/<날짜>`: 비고 `remarks`, 장비 `equip`, 오늘 작업 `today`, 내일 작업 `tomorrow`, 작성자 `author`)의 그 달 문서에서: 비고가 비어 있지 않은 날을 날짜순으로 모으고(특이사항), 마지막 날짜의 "내일 작업"을 다음 달 계획 초안으로 쓴다. **작성하지 않은 날 수**도 센다(**달력 전체 기준** — 결정 11).
- **이력 로그**(`pjt-log-design.md`)의 그 달 항목: 분류별 건수, 완료·미완료, 기한이 지난 요청. 로그에는 금액이 없으므로 현장 층에 그대로 실어도 안전하다(대외비 항목은 제외).
- 자동으로 채운 칸은 **초안**이다 — 생성 뒤 팀장이 고칠 수 있고(직접 입력 칸), 고친 내용은 보고서에 남는다.

## 6. 화면·생성 방식
- **프로젝트 화면의 "월간 보고서" 탭**(현장 층): 월 선택 → "만들기" 버튼 → 한 화면에 §2-1 구성 → PDF·엑셀 내려받기. 이미 만든 달은 목록에서 다시 열기.
- **영업기획의 "월간 보고서"**(경영 층): 월·프로젝트 선택 → §2-2 구성 + 현장 층 요약을 함께. **전체 프로젝트 한눈에 표**(월별 마진율·노무 수율·원가 달성률)도 이 화면에 둔다.
- **월 마감과의 관계**(결정 10): 영업기획 "월말 마감"의 점검 항목에 **"월간 보고서 미생성 프로젝트 N개"** 를 경고로 더한다(마감을 막지 않음, 눌러 가서 만들 수 있게 링크). 월간 보고서가 만들어진 뒤(5번 단계)에 넣는다.
- 모바일: 현장 층을 읽기 전용 요약으로(2단계).

## 7. 저장·권한·보안
- 생성 결과는 **스냅샷으로 저장**한다(나중에 원본이 바뀌어도 그 달 보고서는 그대로, 다시 만들면 버전이 오르고 새 자료가 반영 — 직접 입력한 칸은 보존) — 새 컬렉션 `pjt_monthly/{프로젝트 id}/field/{YYYY-MM}`(현장 층, **구현됨 2단계**)과 `pjt_monthly/{프로젝트 id}/mgmt/{YYYY-MM}`(경영 층, 나중)을 **서로 다른 서브컬렉션**으로 둔다(현장 층 문서에는 금액 필드가 아예 없고, 규칙에서 경영 층만 따로 막기도 쉽다). 문서 필드: ym·layer·pjtId·pjtLabel·partial(이번 달이면 오늘까지의 중간 보고서)·version·generatedAt·generatedBy·source(재료 문서 수)·data(집계 결과)·notes(직접 입력: 특이사항 보완·다음 달 계획).
- **서버 함수 경유로만 읽고 쓴다**(이력 로그와 같은 원칙): 참여자 판정은 서버, 직접 접근은 규칙으로 전부 거부(**이 저장소 규칙은 기본 거부가 없어 새 컬렉션은 제외 목록 + 전용 거부 규칙을 함께 넣어야 한다** — 이력 로그에서 확인된 교훈). 경영 층은 **관리자만**(결정 8 — 지금 관리자 4명, 권한 확장 없음).
- 현장 층의 인원별 공수는 **합계만**(개인 일당·금액 없음). 개인정보(주민번호·계좌·연락처)는 어느 층에도 넣지 않는다.
- 파일 이름에 금액·개인정보 금지(`docFileName` 필터 그대로).

## 8. 개발 순서
**선행(이미 대기열에 있음)**: ① 전표 프로젝트 표시 실행(1-2) → ② 업무일지 "참여 프로젝트" 체크 칸 → ③ 마진율 모듈 → ④ 영업기획 상세. 현장 층은 ①~④ 없이도 만들 수 있다.
1. **현장 층 데이터 집계**(순수 함수 + 시험): 월 공정 증분(상태 차이)·월 공수 합·출역 일수·공사일보 요약·§4 부족 판정 — 실제 테섭 데이터 모양으로 시험
2. **서버 함수 `monthlyReportAct`**(생성·목록·열기·직접 입력 저장, 참여자 판정) + 규칙(직접 접근 거부) + 시험 — **완료(2026-10-17)**: 서버가 직접 읽어 계산(요청에 담은 숫자는 무시)·공사일보 자유 입력 글의 금액·연락처는 저장 전에 가림·종료일은 종료된 프로젝트에서만 사용·집계 규칙은 앱 원본(`monthly.js`)을 서버용으로 **기계 변환**한 `monthly-core.js` 를 쓰며 앱 시험이 두 쪽의 결과 일치를 대조
3. **프로젝트 화면 "월간 보고서" 탭**(PC) — 월 선택·만들기·화면·PDF(파일 이름 규칙) — **완료(2026-10-17)**: 탭 순서 홈·일정·공정·출역·공수·공사일보·이력·**월간 보고서**·설정. 화면은 서버가 계산한 결과를 그리기만 하고(직접 계산 안 함) 달을 빠르게 바꿔도 늦게 도착한 이전 달 응답이 화면을 덮지 않음. 직접 입력(특이사항 보완·다음 달 계획)은 PJT 권한자·관리자만 고치고 금액·연락처는 입력 중에 안내·저장 차단. PDF = 별도 창의 한 장짜리 문서(A4, 자동 인쇄), 제목이 파일 이름 규칙(`2026-08 월간 보고서 - 프로젝트`). 섹터별 증감·이력 요약·엑셀은 이후 단계
4. **이력 로그 인입**(분류별 건수·기한 지난 요청 — `pjt-log-design.md` 의 §10 개발 순서 4번에 해당) — **완료(2026-10-17)**: 서버가 이력 컬렉션을 직접 읽어 계산해 보고서 `data.log` 에 저장. 구성 = 그 달 날짜의 이력 건수(분류별·직접/자동)·처리 상태(처리 중/완료/종결/보류)·변경사항(일정·범위·수량 변경, **영향 확인 전 건수**와 목록 10건)·**기한이 지났는데 처리 중인 요청**(지난 일수·맡은 사람, 10건)·**다음 달에 기한이 오는 처리 중 요청**(다음 달 계획용, 10건). **후보(AI 초안)와 대외비는 존재도 세지 않고**, 제목은 한 번 더 금액·연락처를 가린다. 상태는 보고서를 만든 날 기준(다시 만들면 갱신). 같은 요청이 "기한 지난"과 "다음 달 기한"에 모두 나올 수 있다(보고서를 나중에 만들면 이미 지난 기한이므로 사실대로). 이력 요약이 없는 옛 보고서는 "다시 만들기를 누르면 포함됩니다"로 안내
5. **경영 층**: 마진율 모듈 완성 뒤 — 영업기획 "월간 보고서"·전체 표
6. 엑셀 내려받기·월 마감 경고·모바일 요약
각 단계 시험 → 테섭 자동 배포 → 대표님 확인. 본섭은 새 컬렉션 규칙 게시(규칙 파이프라인) + 화면 배포.

## 9. 미결 (대표님 확인)
