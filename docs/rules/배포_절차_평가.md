> 화면 코드는 춘식이가 테섭에 올립니다. **아래 두 가지(보안 규칙 게시, 서버 함수 배포)는 대표님이 합니다.** 둘 다 테섭(`portal-test-6e0ff`)에서 먼저 하고, 본섭은 본섭 전환 날에만 합니다.

## 1. Firestore 보안 규칙 — "교체"가 아니라 "덧붙이기"
**전체 규칙을 이 파일로 바꾸면 재무회계·전자결재 규칙이 사라집니다. 반드시 덧붙이세요.**
1. Firebase 콘솔 → 프로젝트 **portal-test-6e0ff** 확인(본섭 `p4ph2-fab-506a7` 아님) → Firestore → 규칙
2. 지금 게시된 규칙을 **전부 복사해 메모장에 백업**(문제가 생기면 이것으로 되돌립니다)
3. `match /databases/{database}/documents {` 안의 **맨 아래, 닫는 `}` 바로 위**에 `docs/rules/eval_rules_block.rules`의 `match /eval_cycles ...` 부터 끝까지를 붙여 넣기(맨 위 주석은 안 붙여도 됩니다)
4. 이미 `isApproved()`, `isAdmin()` 함수가 있는지 확인(있어야 정상). 없으면 게시하지 말고 춘식이에게 알려 주세요
5. **게시** → 오류가 나오면 그대로 알려 주세요(화면 캡처)
- 새 컬렉션 `eval_cycles`, `eval_tasks`, `eval_submissions` 세 개에만 적용됩니다. 다른 컬렉션 규칙은 바뀌지 않습니다.

## 2. 서버 함수 `evalAct`
서버 코드 기준본은 비공개 저장소 `portal-functions`입니다(춘식이가 zip을 만들어 드립니다).
```
(zip을 새 폴더에 풀기)
cd functions
npm install
cd ..
firebase deploy --only functions:edoc --project test
```
- `test` = portal-test-6e0ff. `Deploy complete!`이 나오면 성공입니다. 기존 함수(edocAct·ledgerAct 등)도 함께 다시 올라가지만 코드는 그대로입니다.
- 서버 시험: `cd functions && npm test` (eval 15건 포함)

## 3. 평가 시작 전 준비 (화면에서)
1. **직원 관리** → 인사총무팀 전원에게 **"인사평가"** 권한 체크(형일우 사원은 관리자가 아니라서 이 권한이 있어야 평가 운영이 보입니다)
2. **직원 관리** → 팀마다 **팀장** 지정(PJT팀 팀장이 1차 평가자)
3. 평가 대상 직원이 **포털 계정과 근로자 명부가 연결**되어 있는지 확인(직원 관리의 "명부 연동" 표시)
4. 평가 회차 만들기와 과제 생성은 다음 작업에서 화면 버튼으로 제공합니다(지금은 `eval_cycles/2026`의 `status`를 `open`으로 만드는 화면이 없습니다)

## 4. 배포 후 확인 (대표님·직원 계정으로)
- 일반 직원 계정: 왼쪽에 **평가 → 내 평가**만 보이는가
- 사장단·인사평가 권한 계정: **평가 운영 → 정기평가·수시평가**가 보이는가
- 일반 직원이 주소창에 `#/eval/cycle`을 입력해도 **안내만 나오고 데이터가 안 보이는가**
- 인사총무 메뉴에 정기·수시평가가 **없는가**

## 5. 문제가 생기면
- 규칙 게시 후 다른 기능(재무회계·전자결재)이 안 되면 → **백업해 둔 규칙으로 되돌리고** 춘식이에게 알려 주세요.
- 규칙 시험은 `tests/rules/`에 있습니다(에뮬레이터, 49건 + 화면 연결 11건). 규칙을 바꿀 때마다 춘식이가 다시 돌립니다.
